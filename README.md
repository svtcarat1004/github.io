# 원본 화질 다운로더

X(트위터) · 인스타그램 · 스레드 게시물 링크를 붙여넣으면 사진/동영상을 최대한
원본 화질로 저장할 수 있게 해주는 순수 정적(client-side) 웹페이지입니다.
GitHub Pages에서 바로 서비스됩니다.

## 사용 방법

1. `index.html`을 GitHub Pages로 배포합니다 (이 저장소는 `username.github.io` 형태이므로
   `main` 브랜치에 머지되면 자동으로 `https://<username>.github.io/` 에서 서비스됩니다).
2. 페이지에서 X / 인스타그램 / 스레드 게시물 링크를 입력창에 붙여넣고 "가져오기"를 누릅니다.
3. 미리보기가 표시되면 각 사진/동영상 카드의 "원본 화질로 저장" 버튼을 눌러 저장합니다.

## 동작 방식

- **X (트위터)**: 트위터 임베드 위젯이 사용하는 공개 신디케이션 API
  (`cdn.syndication.twimg.com/tweet-result`)를 그대로 호출합니다. 이 API는
  CORS가 열려 있어 별도 서버 없이 브라우저에서 바로 호출할 수 있고, 비교적
  안정적으로 동작합니다. 이미지 URL은 `?format=jpg&name=orig` 파라미터를 붙여
  원본 해상도를 요청합니다.
- **인스타그램 / 스레드**: 두 서비스 모두 브라우저에서의 직접 크로스오리진
  요청(CORS)을 허용하지 않기 때문에, 공개 CORS 프록시를 통해 게시물의 공개
  HTML(임베드 페이지 등)을 가져온 뒤, 페이지에 내장된 JSON 데이터에서
  `image_versions2.candidates`(사진 원본), `video_versions`(동영상 원본) 값을
  정규식으로 추출합니다. 데이터를 찾지 못하면 `og:image` / `og:video` 메타
  태그로 한 번 더 시도합니다.

## 알려진 한계 (중요)

이 프로젝트는 백엔드 서버 없이 **정적 파일만으로 GitHub Pages에서 동작**하도록
만들어졌기 때문에 다음과 같은 구조적 한계가 있습니다.

- 인스타그램/스레드는 공식 다운로드 API가 아니라 **공개 페이지 스크래핑 +
  공개 CORS 프록시**에 의존합니다. 두 회사가 마크업/내부 데이터 구조를 바꾸거나,
  사용 중인 무료 CORS 프록시(corsproxy.io, allorigins.win 등)가 요청을 차단·
  속도 제한하면 언제든 실패할 수 있습니다. `app.js`의 `CORS_PROXIES` 배열에
  여러 프록시를 순서대로 시도하도록 해 두었지만 완전한 해결책은 아닙니다.
- 비공개 계정, 로그인이 필요한 게시물, 삭제된 게시물은 애초에 가져올 수 없습니다.
- 사진+동영상이 섞인 인스타그램/스레드 캐러셀(여러 장 게시물)은 완벽하게
  슬라이드별로 매칭되지 않을 수 있습니다 (동영상이 있으면 동영상을 우선 표시).
- 더 안정적으로 쓰고 싶다면 `worker/` 폴더에 있는 Cloudflare Worker를 배포하세요.
  공용 CORS 프록시 대신 본인 소유의 프록시로 인스타그램/스레드 페이지를
  가져오게 되어 훨씬 안정적입니다. 배포 방법은 `worker/README.md`를 참고하고,
  배포 후 `app.js` 상단의 `WORKER_PROXY_URL`에 발급받은 주소를 넣으면 됩니다
  (설정하지 않으면 기존 공용 프록시 체인으로 자동 대체됩니다).

## 저작권 및 이용 안내

이 도구는 개인적인 백업/보관 목적의 사용을 전제로 합니다. 본인이 작성했거나
다운로드가 허용된 콘텐츠만 저장하시고, 저작권자의 권리를 존중해 주세요.
각 플랫폼의 이용약관을 확인하고 책임 하에 사용하시기 바랍니다.

## 파일 구성

- `index.html` — 페이지 마크업
- `styles.css` — 스타일
- `app.js` — 링크 파싱, API 호출, 다운로드 로직 (프레임워크 없이 순수 JS)
- `worker/` — 인스타그램/스레드용 선택적 Cloudflare Worker 프록시 (배포 방법은
  `worker/README.md` 참고)
